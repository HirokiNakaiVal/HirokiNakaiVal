# 日別稼働計画アプリ（試作版）

OCTORの月間稼働表とタスクリレーをもとに、店舗ごとの日別稼働表（Excel）を作る社内向けWebアプリです。
会社 → 事業部 → 店舗 の階層で、複数店舗を管理できます。

## 会社・事業部・店舗マスタ

snowhc から抽出した「会社事業部.xlsx」（KAISHA_CD・JIGYOBU_CD・JIGYOUBU_NM）と「会社事業部店舗.xlsx」（KAISHA_CD・JIGYOBU_CD・TENPO_CD・TENPO_NM ほか）をマスタとして使います。

- 取込：トップ画面の「マスタを取り込む」、またはコマンド `python import_master.py 会社事業部.xlsx 会社事業部店舗.xlsx`
- コードが同じものは名称・所属を更新、無いものは追加（何度取り込んでも重複しない）
- 会社名はマスタに無いため、配下の事業部名の共通部分から仮に付ける（例：バローＳＭ・バローＨＣ → バロー）。トップ画面で変更でき、再取込しても上書きしない
- 事業部マスタに無い事業部コード（店舗マスタにだけ出てくるもの）は「事業部○○」として作る
- 手で登録した組織はコードを読み替えて引き継ぐ（会社00→0、事業部02→2、店舗001→事業部コード×1000＋1）

## 労働時間予算

「○期労働時間予算.xls」（店番×月、正社員・パート・アルバイト予算）を「マスタ・設定」画面の「マスタを取り込む」から、取り込む事業部を選んで取り込みます。

- **月度で統一**：予算の「3月」＝3月度＝2/16〜3/15（前月16日〜当月15日。OCTORの月間稼働表と同じ区切り）。予算・計画・実績をすべてこの月度で集計（開始日は店舗の設定「月度の開始日」で変更可）
- 店番 → 店舗コード＝事業部コード×1000＋店番（例：バローＨＣの店番1 → 2001 高山）
- ファイルに年が無いため、取込時に期首（3月の列）の年月を指定。同じ店舗・月度は上書き
- 店舗の画面：月度ごとに 予算／計画実働（月間稼働表の拘束−休憩）／実績（KADOUの作業時間）と、その差を表示（月度の途中までしか無いものは差を出さない）
- 予算の日割り（日別稼働表・比較画面で共通）：月度の予算を、店の実績から求めた「1日あたり固定時間＋売上予算に比例する時間」の比率で配分（高山：固定231h＋100万円あたり17.3h）。当てはまらない場合は売上比率と日数の半々、売上予算が無ければ月度の日数で均等
- 日別稼働表：その日の日割り予算と計画実働（拘束−推定した休憩）を比較。5%超過で要確認、10%以上少なければメモ。時間帯予測シートの L8〜M13 に表示
- 正社員・パート別の比較は、月間稼働表に身分（一般・パートなど）が無いため合計のみ

### 月度計画との比較・修正案（店舗の画面 →「月度で比較・修正案を見る」）

- 月度（月間稼働表の期間、例：9/16〜10/15）を選ぶと、労働時間予算と計画実働を比較し、Excel（数式つき）でも出力
- 月度を選ぶと、その月度の予算（例：9/16〜10/15＝10月度）と比較。実績（KADOU）がある日は実績も並べて表示
- 計画実働：拘束時間−休憩（KADOU実績から推定）。有休・会議・研修は既定で含めない（店舗の設定で1日の時間を指定すると含める）
- 修正案
  - 月度合計が予算超過 → 「削減」：超過の大きい日から、来客の少ない時間帯にかかる勤務の端を30〜60分短縮。足りない日は出勤日数の多い人を公休へ変更する候補
  - 月度合計が予算内 → 「平準化」：日の予算を超える日だけ短縮案（余裕のある日へ回す）
  - 制約：マネジメントと4時間以下の勤務は対象外／閉店・開店の担当は同じ部門に1人残る場合のみ／同じ日の同じ時間帯を詰めるのは2人まで
  - 余裕のある日は、来客の多い時間帯と追加できる時間を表示

## 使い方（店舗担当者）

1. トップ画面で店舗を検索するか、会社 → 事業部 → 店舗 の順に選ぶ
2. 「データを取り込む」でファイルをまとめて選んで取り込む（種類は自動判別）
3. 「日別稼働表を作る」で日付（または期間）を選んで作成
4. 結果画面で、要確認事項（レジ台数の不足、無人の専任レジ、タスクリレーの持越しなど）を確認し、Excelをダウンロード

### 取り込むファイル

| 種類 | 出どころ | 必須 | 用途 |
|---|---|---|---|
| 月間稼働表（PDF） | OCTOR 帳票出力 | 必須 | 出勤・公休・開始・終了 |
| タスクリレー（Excel） | TaskRelay2 作業割当 | 任意 | タスクリレーの割当 |
| KADOU実績（Excel・CSV） | KADOU(emp_view) 抽出、DB実績CSV | 推奨 | 作業内容・休憩の推定（指定日の直前35日分）、労働時間の実績 |
| 時間帯別売上（Excel） | snowhc 抽出 | 推奨 | 来客予測 |
| 時間帯別レジ別売上（Excel） | snowhc 抽出 | 推奨 | レジの優先順 |
| 日割予算（PDF） | 日割予算リスト | 任意 | 来客予測の補正 |

同じ種類のファイルは期間をつないで使います（重なった期間は後から取り込んだものを優先。KADOUは社員×日単位）。

KADOU実績の取り込みで行う整理：
- CSV（Shift_JIS／UTF-8）も可。1ファイル500MBまで（環境変数 `KADOU_MAX_UPLOAD_MB` で変更）
- 完全に同じ行は1行にまとめる（DB実績CSVは同じ行が約19倍重複していた）
- 「小林 久範(登販)」のように括弧書き付きの別IDで同じ日・同じ作業が重複している場合は、括弧の無い名前の方だけを残す
- KADOUには先の日付も予定として入っているため、労働時間の「実績」は今日より前の日だけで集計
日別稼働表PDFは取り込み対象外です。

### 出力（Excel）

日別稼働表（社員別・15分単位）／レジ別稼働表（予測客数・必要台数・配置台数・判定）／時間帯予測／タスクリレー割当（割当・配置・持越し）／レジ配置／作業配置／作業推定／説明（作成ルールと要確認事項）

## 作成ルール（概要）

- 勤務：月間稼働表どおり
- 休憩：本人の同じ拘束時間の実績 → 店全体の実績 → ルール。来客の少ない時間帯に置き、同じ部門で重ならないようにする
- 作業：KADOU実績（直前35日・同じ曜日優先）から推定。最も長い作業を基本作業、実施率50%以上の作業を中央値の分数で採用
- 1時間交代の持ち場（灯油1など）：営業時間の1時間枠ごとに1人
- タスクリレー：実施期間内の出勤予定日数で均等割り。1日の上限は基本作業から60分を残した分まで。超えた分は持越し。来客の少ない時間帯にまとめて配置
- 来客予測：直前8週の同じ曜日（祝日・お盆・年末年始・5％デーを除く）の平均 × 予算 ÷ 基準日の平均売上
- レジ：必要台数＝有人レジの予測客数 ÷ 1台あたり処理客数（既定30人/時）。専任 → レジ部門（予測客数の多いレジから）→ 他部門の応援（台数不足の時間帯）の順に割当

営業時間・有人レジ・専任レジ・処理客数などは店舗ごとに「店舗の設定」で変更できます。

## サーバーへの設置（管理者）

前提：Windows Server（または Linux）、Python 3.11 以上

```
pip install -r requirements.txt
run_server.bat            # http://サーバー名:8000/ で利用
```

- ポート：`run_server.bat` の `PORT`
- データ保存先：環境変数 `KADOU_DATA_DIR`（既定は `data\`。取込ファイル・作成結果・SQLiteを保存）
- ログイン：全画面でログインが必要（個人情報を含むため）。初回は ID `999999`／パスワード `999999`（管理者）。ログイン後、画面上部の名前からパスワードを変更してください
  - マスタ・設定：画面上部の「マスタ・設定」を押し、管理者パスワード（初期 `999999`）を入れると入れる。操作の無いまま30分（`KADOU_ADMIN_MINUTES`）か「管理を終了」で再入力。管理者パスワードは「ユーザー管理」タブで変更（5回続けて間違えると5分ロック）
  - ユーザー管理：マスタ・設定 →「ユーザー管理」タブで追加・削除・パスワード再設定。追加時に認証方法を「SSO」か「ローカル」から選ぶ
  - SSO認証（`SSOのhttp認証仕様.xlsx`）：SSOユーザーは社員コードと社内パスワードを SSO サーバー（既定 `https://sso.valorholdings.co.jp/`）へ POST し、200 で成功・404 で失敗。パスワードはアプリに保存しない
    - **app_path は必須**：このSSOは app_path 空白（`action=REST`）だとパスワードを検証せず成功を返すため、ログインには使わせない（`app_path` を設定して `action=AgentAuth` を使う）。`app_path` の値は情報システム部（SSO管理者）に確認
    - 接続先はこの環境では **https のみ**（http は接続が切られる）
    - 設定（有効/無効・URL・app_path・文字コード・自動登録）と接続テストは「ユーザー管理」タブ。`TestSsoAccess` を含むURLは認証が飛ばされるため保存不可
    - 既定では登録済みの社員コードだけがログイン可（未登録IDはSSOに問い合わせない）。「自動登録」をONにすると、SSOで認証できた社員を自動でSSOユーザーとして登録
    - SSOサーバーに接続できないときはその旨を表示（失敗回数には数えない）。非常用にローカルの管理用ユーザー（初期 `999999`）を残しておく
  - パスワードはハッシュ化（PBKDF2）して保存。8文字以上、IDと同じ・同じ数字だけは不可
  - 同じIDで5回続けて失敗すると5分間ロック。操作が無いまま12時間（`KADOU_SESSION_HOURS`）で自動ログアウト。パスワードを変えると他の端末のログインは無効
  - セッション署名の鍵は `data\secret.key`（消すと全員ログアウト）
- 同時に作成する数：環境変数 `KADOU_WORKERS`（既定2）
- 常駐させる場合は NSSM などでWindowsサービス化するか、タスクスケジューラで起動時に実行

### 構成

```
app/       Webアプリ（FastAPI）：画面、取込、作成ジョブ、SQLite
engine/    作成エンジン：ファイル読込（loaders）、計画作成（planner）、Excel出力（excel）
templates/ 画面テンプレート
static/    スタイル
data/      保存データ（自動作成）
```

## 試作版の制約・今後

- ログインはアプリ内のID/パスワード（社内AD連携や、店舗ごとに見られる範囲を分ける権限は未対応）
- OCTORへの書き戻しは未対応（取込機能・APIの有無を確認中）
- データはファイル取込のみ（KADOU・TaskRelay2・snowhc のデータベース直結は次段階）
- 部門別予算は未使用
